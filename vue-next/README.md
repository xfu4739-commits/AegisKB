## 启动

在本目录执行：

```bash
npm ci
npm run dev
```

- 新版：http://localhost:5174/chat，端口占用时直接报错，不自动换端口。
- 原版对比：http://localhost:5173/chat，需要原服务已经启动。
- 环境变量参考 `.env.example`；本地覆盖可保存为 `.env.local`。不要填写模型 Key。
- `VITE_PROXY_TARGET` 指向现有 Java 服务，默认 `http://127.0.0.1:9083`；`VITE_LEGACY_APP_URL` 指向原版工作台。

## 当前能力：M5 验收与新旧对比

已经接入 Ant Design Vue 4.2.6、Ant Design X Vue 1.6.0、Vue 3.5.13。
普通入口 `/chat` 现在读取真实会话列表、历史详情、知识库和文档选项；恢复历史模式和范围。新建只清空本地当前会话，不写服务器。删除必须确认，会调用既有 session/reset 接口清理会话，不可撤销。失败显示错误并保留原有数据，不回退为演示数据。

范围可在输入面板设置；选项加载失败时设置禁用，历史范围保留并提示。历史文档当前不可用时不会自动换成其他文档。欢迎卡片只填入草稿。普通入口已接入真实流式发送：Enter 发送、Shift+Enter 换行，中文输入法确认不会发送。

生成期间禁止新建、切换、删除会话或修改范围；输入框可继续编辑下一条草稿。点击“停止生成”会中断浏览器连接并请求服务端停止；服务端未确认时保留锁定，可再次请求停止。离开页面会中断连接并尝试服务端停止。

失败保留已生成的部分回答；“重新发送此问题”按原问题和原范围发起新一轮请求，会产生新的 exchange，不是自动重放或修改旧记录。答案完成后读取服务端归档；归档尚未更新或读取失败时保留本轮内容并提示，可重试加载历史。

正文引用只接受后端返回且有稳定 identity 的 Source，Context Only、无 identity 和未知编号不生成按钮；不重新编号，不在代码或链接中替换引用。点击编号打开居中来源弹窗，展示片段及后端定位信息；检索说明失败不隐藏答案或已有来源。用户上滚暂停跟随，点击“回到最新消息”恢复。

开发时打开 **http://localhost:5174/preview/chat**，或点击顶栏“交互演示”，体验独立演示数据：

1. 第一段历史会话展示长回答、表格、代码和追问；复制按钮可复制原始代码或消息。
2. 第二段长标题会话展示回答错误，可点“重试演示回答”检查恢复状态。
3. 欢迎卡片与追问只填入草稿。主动发送后得到固定演示回复，不调用模型、不保存到服务器。
4. 点击输入区“知识库”，选择演示知识库、回答模式和文档；当前文档模式未选文档时不能发送，清空知识库会回到开放提问。
5. 会话菜单中删除需要确认，仅删除本地演示状态；刷新可恢复。移动端通过抽屉选择会话。
6. 顶部演示场景选择器可查看欢迎空状态、短暂加载和加载失败；失败后可重试。

演示入口与 `/__preview/chat` 资料接口仅由 Vite 开发服务提供。生产构建没有演示路由或 fixture 内容，也不会在真实接口失败时回退成演示数据。流式生命周期使用额外的 Playwright 隔离场景测试，不调用真实模型。

## 从哪里读代码

1. `src/main.js`：创建 Vue 应用，加载本工程样式，安装路由。
2. `src/App.vue`：ConfigProvider 管理主题与弹层容器；主题数值来自 `src/styles/tokens.css`。
3. `src/router/index.js`：根地址跳转 `/chat`，懒加载页面。
4. `src/features/chat/ChatWorkspace.vue`：编排布局、本地草稿、移动导航和演示状态。
5. 同目录 `ChatSidebar.vue`、`ChatWelcome.vue`、`ChatComposer.vue`：分别负责导航、欢迎区和输入面板；组件用 props 向下传数据、事件向上传递交互。

6. `previewState.js`：本地会话状态与范围协调，使用请求序号丢弃过期演示结果；通过依赖注入可单独测试错误与竞态。
7. `ChatMessages.vue` / `ChatMarkdown.vue`：Bubble 展示消息；Prompts 展示追问。Markdown 经解析、清洗和安全链接处理，复制代码使用单独保留的原文。
8. `preview/fixtures.js`：仅供开发服务与 Playwright 使用的固定资料，不属于浏览器生产模块。
9. `chatApi.js` / `stream.js`：独立客户端按旧协议读取 envelope、SSE，保留字符串 ID、分页和 UTF-8 分片；负责发送、停止和检索说明运输。
10. `liveState.js`：composable 负责会话、范围、流式请求所有权、冻结范围、冲突锁、停止确认、错误重试与最终归档恢复。每个异步结果先验证所属轮次。
11. `references.js` / `markdown.js`：从后端引用数组投影可展示的来源，保留原始数组编号；Markdown 解析和清洗后由点击事件委托打开来源弹窗。

数据流是“事件 → 父组件或 composable 更新状态 → props 刷新界面”。渲染器不推测引用，未知 `[n]` 保持普通文字。

## 验证

```bash
npm run test:unit
npm run check:design
npm run build
npm run test:e2e
```

`check:design` 直接运行 Node 测试，检查工程依赖边界、Token 与对比度，没有另建辅助脚本。
Playwright 使用本工程 5174 端口，独立拦截业务和演示资料请求，覆盖桌面、手机、减少动画、键盘与 axe。完整验收还需原版 5173 服务已启动，并先执行 build；生产包用例会短暂启动和关闭自身的 4174 预览进程。最新截图保存在根目录 `doc/重构前端/evidence/blue-reference/`，此前版本保留不覆盖；调试产物在忽略提交的 `test-results/` 和 `playwright-report/`。

`e2e/fixtures/acceptance.js` 为两版提供同一个后端快照，`acceptance.spec.js` 检查同数据对比、四种宽度弹窗/范围设置、新旧往返与原后台认证入口，`production.spec.js` 检查构建不包含演示代码。结果与已知限制见根目录 `doc/重构前端/M5验收与新旧对比.md`。原 `vue/` 与默认入口继续保留。

## 本轮人工验收

自动化不向真实后端发送问题。请在普通入口 `/chat` 主动完成：开放提问发送及追问、选择已有知识范围后发送、点击合法引用核对来源、长回答中上滚及回到底部、生成期间停止、刷新后核对已归档内容。错误重试可在隔离浏览器测试中复查，无需破坏真实服务来制造失败。用户操作后 AI 可只读核验新增 conversation/exchange。真实聊天和视觉确认完成后，才能将本轮重写记为最终验收完成。
