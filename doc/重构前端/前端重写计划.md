## 2. 技术方案与边界

采用 **Vue 3 + Vite + Vue Router + Ant Design Vue 4 + Ant Design X Vue**。

Ant Design X Vue 是社区维护的 Vue 实现，参考其[独立式演示](https://antd-design-x-vue.netlify.app/playground/independent)的组件组织方式，自行设计页面布局和交互，不复制整页模板。[项目说明](https://github.com/wzc520pyfm/ant-design-x-vue)

实施约定：

- 原版工程 `vue/` 及其 `/chat`、根跳转和后台路由全部保留；新版为根目录独立工程 `vue-next/`，不在旧路由中增加页面。
- 新版拥有自己的依赖清单、锁文件、入口、源码、配置、测试和构建目录，不 import `vue/` 中的源码、组件、样式或测试工具，不配置指向旧源码的 alias。
- 原版对比地址为 `http://localhost:5173/chat`；新版为 `http://localhost:5174/chat`，新版 `/` 跳转新版 `/chat`；新版端口固定为 5174 并启用 strictPort。
- 使用 Vue 单文件组件、`<script setup>` 和 JavaScript，独立配置 Vite 和 Vue Router；不引入 JSX、全局状态库或 TypeScript，也不搬入原版 Tailwind/shadcn/Reka 工具链。
- 基础组件采用 Ant Design Vue，聊天组件采用 Conversations、Welcome、Prompts、Bubble、Sender。
- 项目自定义图标继续使用 Heroicons，不新增一套图标依赖。
- 新工程使用自己的语义 Token、ConfigProvider、命名空间样式和局部弹层容器；与原版构建物理隔离，不引入或修改旧版全局样式。
- 复用已确认的接口协议与纯函数行为，不直接引用旧工程文件。M3 在新版建立 API 客户端，必要的纯逻辑按行为迁移并建立测试；不复制旧页面的大组件。
- 新版在自己的 Vite 配置中代理 `/api`、`/manage`、`/admin/auth` 到既有后端，使用 `VITE_PROXY_TARGET`；原版链接由 `VITE_LEGACY_APP_URL` 配置，提供无密钥的 `.env.example`。
- 模型调用继续经过现有 Java 后端；不采用演示中的浏览器直连模型及 API Key 方案。
- 不修改 Java、Python、数据库、检索策略或引用绑定规则；不套用后端 Sxx 阶段状态机。
- 不自动提交、推送、部署，也不修改 `vue-claude/`。

接口变化：仅在独立新工程中建立前端路由与内部组件接口，不修改原版路由或后端 API。保留现有字符串 ID、知识范围字段、三种回答模式和流式事件协议。两版共享后端数据，不共享前端运行实例；不同端口的浏览器登录态分别管理，不通过 URL 传递 token。

## 3. 页面设计与功能约定

按 2026-11-04 用户提供的 DeepSeek 截图，采用 **AegisKB 蓝白聊天布局**：白色阅读区、浅灰侧栏、蓝色主要操作与原创盾牌书页标志。新版颜色集中在自己的语义 Token 中，不修改原版主题；此前版本只保留作历史。

页面结构：

- 侧栏：桌面宽度 260px，可收起；原创图标与品牌、新建对话、按更新时间分组的会话列表。条目显示精简标题，删除操作放入菜单并二次确认，不展示未经处理的 Markdown 摘要。
- 顶部栏：简短“对话”、导航控制和辅助入口图标；不铺长会话标题，开发场景选择收进设置弹层。保留指向原版 5173 端口的聊天与现有管理后台链接，不把旧后台地址误写成新版内部路由。
- 欢迎区：只保留图标与一句加大加粗的欢迎语，与输入框一起居中；不展示副标题、重复字标或推荐入口。
- 消息区：正文最大宽度 760px、输入区 780px；用户消息右对齐，助手消息左对齐；统一头像、时间、复制、错误与重试操作。
- 输入面板：整合多行输入、知识库选择、回答模式、文档选择、发送和停止按钮。持续显示当前范围摘要，不能让用户误以为正在使用未选择的知识库。
- 引用详情：使用居中 Modal，展示后端返回的来源与定位信息；保留稳定 identity 和原编号，不重新排序或补充引用。
- 响应式：1024px 以下使用移动导航抽屉；手机上的轻量任务入口和输入工具允许换行；正文、表格和代码分别控制溢出。

第一版不新增附件上传、语音、模型切换、会话重命名、点赞反馈或 Mermaid 渲染。代码块继续安全展示，并提供复制功能。

### M4：接入流式聊天与引用

工作内容：

- 接入现有发送、流式事件和服务端停止接口。

- 生成期间禁止冲突操作；停止或卸载后拒收旧流片段。
- 自动跟随最新消息；用户上滚时暂停跟随，提供回到底部入口。
- 安全渲染 Markdown，只展示后端明确绑定的来源；Context Only、无稳定 identity 和未知引用编号不变成有效来源。
- 检索说明加载失败不影响已有答案展示。

交付：完整聊天、停止、错误重试、来源查看与追问体验。

退出条件：隔离测试通过；真实聊天由用户执行，AI 只读检查结果。
