## 2. 工程、技术和实施边界

### 2.1 继续在哪写

- 继续在独立工程 `vue-next/` 中新增管理后台，与第一阶段聊天页组成同一套新版前端。
- 不在原 `vue/` 上改，不创建第三套重复依赖工程，不修改 `vue-claude/`。
- 原版保持 `http://localhost:5173/admin/...`；新版最终使用 `http://localhost:5174/admin/...`。这是不同前端地址，共享既有 Java 后端和真实业务数据。
- 新版 `/` 继续跳转 `/chat`，聊天页面和品牌布局保留。后台采用懒加载，聊天首屏不预加载整套管理页面。
- 计划实施期间保留聊天页当前通往旧后台的入口；新后台通过明确的 5174 地址演示。入口切换作为最终交付后的单独决定，不在尚未验收时自动替换。

### 2.2 技术栈

- 沿用 Vue SFC、`<script setup>`、JavaScript、Vue Router；不迁移 TypeScript，不引入 JSX 或全局状态库。
- 后台基础组件使用现有 Ant Design Vue：Layout、Menu、Breadcrumb、Table、Form、Input、Select、Tabs、Modal、Drawer、Descriptions、Statistic、Tag、Progress、Timeline 等，按实际需要导入。
- Ant Design X Vue 继续服务聊天场景，不强行用于管理表单和表格；不安装 React 版 Ant Design Pro/ProComponents。
- 复用 AegisKB 蓝白 Token、原创盾牌书页标志与 Heroicons。后台追加自己的布局 Token，不更改已确认的聊天 Token 值。
- 初版使用现有组件、简单可访问图形和列表呈现统计。仅有真实时序数据才绘趋势；复杂图表/图谱若确需额外依赖，先在所属里程碑给出方案、体积和维护理由，再确定，不预装占位库。
- 业务页只消费接口投影；API 模块负责协议，composable 负责请求、表单和任务生命周期。按行为迁移必要纯函数并保留测试，不跨目录 import 旧源码，不复制旧版大组件。

### 2.3 建议目录职责

```text
vue-next/src/
  shared/
    api/                  通用 JSON、multipart、Blob 和认证错误处理
    auth/                 唯一认证状态、会话确认和安全回跳
    components/admin/     经过实际复用确认的后台基础组件
  features/admin/
    shell/                后台导航、页头、面包屑、登录与退出
    dashboard/            运营总览和知识运行全景
    knowledge-bases/      知识库列表、表单和设置
    documents/            文档列表、上传入口、详情及任务视图
    knowledge-route/      范围、主题、画像、关联和追踪
    observability/        会话列表、会话链路、轮次详情
    settings/             当前配置、修改、历史与恢复
  features/chat/          第一阶段页面，保持可回归
  router/                 已实现页面的路由与认证守卫
```

这是职责规划，不要求提前创建空目录或空壳组件。只在对应里程碑真正实现需要的文件；共享组件必须来自真实重复场景，不先造庞大的后台抽象框架。

### 2.4 明确不做的事情

- 不修改 Java/Python、数据库表、检索策略、解析算法、引用规则或后端权限体系；不套用后端 Sxx 阶段状态机。
- 不新增角色权限、用户管理、多租户、主题切换等现有接口未支持的业务。
- 不伪造统计、不以 mock 掩盖真实请求失败、不把后端未实现的操作做成假成功按钮。
- 不自动提交、推送、部署、切换分支、删除旧版或切换默认入口。
- 不把同端口本地存储隔离误认为业务库隔离；两版的真实删除、配置、构建等都会影响共同后端。

## 3. 页面范围和最终路由

以下为第二阶段最终路由清单；实施时只注册已经可用的页面，不提前放置无法使用的菜单。

- `/admin/login`：登录。
- `/admin`：后台入口，完整总览交付后跳转 `/admin/dashboard`。
- `/admin/dashboard`：运营总览。
- `/admin/quality-overview`：知识运行全景。
- `/admin/knowledge-bases`：知识库管理。
- `/admin/documents`：文档列表与上传。
- `/admin/documents/:documentId`：文档详情与任务工作台。
- `/admin/knowledge-route`：知识范围、主题、画像、文档关联。
- `/admin/knowledge-route/traces`：知识路由追踪。
- `/admin/observability`：会话观测列表。
- `/admin/observability/:conversationId`：会话链路。
- `/admin/observability/:conversationId/exchanges/:exchangeId`：轮次详情。
- `/admin/settings/configuration`：当前配置和配置历史。

规划覆盖与旧版同类的 12 个可导航页面及一个后台壳。未知后台路由应提供明确的后台未找到页，而不是被新版全局 catch-all 静默送回聊天页。

实体 ID 在 JSON、表格 rowKey、路由参数和请求中始终保持字符串；分页、版本、阈值和计量字段按各接口已确认的类型转换，不把所有数字统一强制成字符串或 Number。

## 4. 后台视觉与交互原则

- 沿用蓝白品牌，采用浅灰工作区、白色内容容器、淡蓝选中态。DeepSeek 参考用于品牌和简洁程度，后台信息架构以管理任务、表格和表单为核心，不照搬聊天页大面积居中留白。
- 桌面侧栏建议 232px，收起约 64px；顶部约 56px，显示页名/面包屑、当前管理员和退出；1024px 以下改为导航抽屉。
- 列表页采用“标题及主操作 → 筛选 → 表格 → 分页”，详情页采用“对象摘要 → 任务/状态 → 按需标签页”。高级技术细节折叠展示，避免首次打开铺满 JSON。
- 表格显示当前任务最需要的字段；次要字段进入详情。长 ID、长文件名与错误信息允许安全查看/复制，不迫使整个页面横向滚动。
- 短编辑使用 Modal；需要持续对照列表的编辑可用 Drawer；复杂详情使用独立路由。批量或高影响操作先展示作用对象、范围与结果含义，再明确确认。
- 手机不把桌面表格简单压缩：保留关键列或使用摘要列表；必要表格只在自身容器内横向滚动。
- 保留加载、刷新、空结果、部分失败、权限不足和重试状态。缺失数据展示“暂无/不可用”，不伪装成 0、成功或绿色健康状态。
- 所有操作有可访问名称、明确焦点；弹层可通过 Escape 关闭并恢复焦点。不能只靠颜色表达任务成功/失败。

## 5. 接口、认证与数据原则

### 5.1 运输层与认证

- 先为当前聊天客户端建立 characterization，再将可复用 HTTP/认证部分提取到受测共享模块；保持现有聊天请求、SSE 和错误行为。
- 沿用既有 token 键，统一登录、退出、401 清理和管理员信息；5173/5174 不通过 URL、复制本地存储或其他方式自动同步 token。
- 受保护路由通过服务端 `/admin/auth/me` 确认会话；本地 JWT 到期解析只用于快速判断，不能代替服务端认证或据此创建角色权限。
- 401 让后台回到登录页并保留安全返回路径；403 展示无权限，不冒充未登录。公共 `/chat` 不因后台尚未登录而被重定向。
- 回跳只接受同源、已注册的后台内部路由，拒绝外部地址、协议相对地址和登录循环。过期请求的 401 不得清除后来重新登录的状态。
- 登出后废止正在进行的页面请求与轮询；旧请求不能恢复已退出的管理员数据。认证检查失败时展示连接失败和重试，不误清空为“没有数据”。
- 继续使用既有 code/data envelope、HTTP 方法、超时和错误协议。multipart 不手动设置错误的 boundary；Blob 下载携带认证，关闭预览/卸载时释放对象 URL，不把 token 放入下载链接。

### 5.2 后端业务权威

- 任务、状态、进度、文档范围、配置版本、route 与 citation 由后端返回。前端只投影，不自行推断业务状态或修正引用。
- 运行任务的轮询按后端终态停止；页面切换、切换文档或退出后取消，拒绝迟到结果。失败不能无限轮询，也不能让并发请求不断叠加。
- 总览保留当前样本、全量与时间窗的区分；趋势、比例和平均值展示分母/数据口径，缺失项不补零。旧总览已有正确的样本说明，不为换 UI 丢掉它。
- 观测详情分别展示 Source Evidence、Context Only、Prompt/显式引用与归档事实，不在前端重排、补全或猜测 citation。
- 配置编辑依接口约束校验并保留修改说明、expectedVersion。冲突时保留草稿、提示刷新对比，不静默覆盖；历史恢复说明其真实作用范围和新增历史语义。
- 所有写请求的 operatorId、ID、版本和作用范围先核对 producer。既有常量/协议字段不得被假装成当前登录用户身份，也不凭 UI 文案猜造字段。


再执行受影响 Playwright、`git diff --check`、旧工程差异检查与 `git status --short`。A0、认证/共享客户端接入、共享组件或 Token 变动、A8 均运行完整 `npm run test:e2e`，明确包含第一阶段聊天回归。

### 7.2 必须覆盖的场景

- 认证：未知/过期会话、登录失败、重复提交、401/403、退出、并发检查、安全回跳与公共聊天访问。
- 数据：字符串实体 ID、实际分页类型、空值和缺失、样本口径、请求失败、筛选恢复、旧请求越权覆盖。
- 写动作：取消不写、确认单次写、作用对象正确、失败保留、配置版本冲突；所有自动化使用隔离接口和数据。
- 任务：同文档不同 task、终态停止轮询、切页/卸载取消、迟到片段、长日志、大产物及窗口加载。
- 安全展示：Markdown/HTML 注入、下载/预览、凭据脱敏、未知引用 fail closed，引用不得由观测 UI 重建。
- 交互：390/768/1024/1440px、表格/代码局部溢出、键盘、表单标签、焦点恢复、导航抽屉、减少动画和 axe。
- 两版与生产：旧版路由/认证不改、新版聊天无回归，开发 mock 不进入生产，也不掩盖真实接口失败。
