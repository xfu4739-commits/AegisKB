# S00：基线冻结与有效门禁

> 状态只在 [改造计划与进度.md](../改造计划与进度.md) 维护。本文件是 S00 的工程实施合同；具体执行结果、偏差和证据见 [records/S00.md](../records/S00.md)。

## 阶段设计依据

旧静态扫描只计数、不对新增未分类问题失败，无法作为长期改造的反馈门禁。本阶段先冻结 HEAD、测试、数据水位和既有债务，再为每个 finding 建立稳定 identity、classification 与 owner，使后续阶段能够区分预存问题和新增回归。

本阶段所有长期设计必须由本项目的 `CODE_CONFIRMED`、`DATA_CONFIRMED`、明确不变量或目标红灯支持。外部资料只能作为一般性研究背景，不能替代本项目事实，也不进入学员版设计权威。

> 本阶段状态只在 [改造计划与进度](../改造计划与进度.md) 维护；本文件只保存阶段范围、实施清单和退出条件。全局施工与人工操作规则见 [AGENTS.md](../../../AGENTS.md)，通用命令与测试矩阵见 [验证规则](../验证规则.md)。

唯一目标：让现有债务可分类、可重复，同时保证任何新增未分类违规返回非零。

前置条件：无。

必读：

- [改造计划与进度](../改造计划与进度.md) 中“问题基线与阶段归属”和“目标架构与权威边界”的对应条目。
- [AGENTS.md](../../../AGENTS.md) 的禁止样例驱动补丁与阶段事实核验规则，以及 [改造计划与进度](../改造计划与进度.md) 的全局完成清单。
- `scripts/rag-audit-gate.sh`。
- `O2-O8-RAG能力完整测试验收方案.md`。

允许修改：

- `scripts/rag-audit-gate.sh` 及其测试/基线文件。
- 与门禁直接相关的文档引用和验收口径。
- 门禁所需的最小 Maven/Python 测试配置。

不处理：任何 RAG 运行逻辑、解析、检索、Prompt 或数据库 schema。

实施清单：

- [x] 记录开始 HEAD、工作区脏文件、Java/Python 当前测试数和数据库水位。
- [x] 门禁覆盖 Java、Python、Prompt、YAML 和当前 RAG 文档引用。
- [x] 建立已审查分类基线；基线项必须包含文件、规则、原因和归属阶段。
- [x] 新增未分类命中返回非零，允许项和历史已分类债务不误报失败。
- [x] 删除对不存在 `document/旧版重构执行进度.md` 的引用。
- [x] 增加门禁自测试，至少覆盖失败、allowlist、失效引用和多文件类型。
- [x] 固化 15 文档、48 个唯一 Q 编号、44 个唯一问题文本、旧反例 ID 和 exchange watermark。

测试：

~~~bash
scripts/rag-audit-gate.sh --check
scripts/rag-audit-gate-test.sh
mvn -pl aegis-kb-business/aegis-kb-business-chat -am -DfailIfNoTests=false test
cd aegis-kb-rag-tools
.venv/bin/python -m unittest discover -s tests -v
~~~

退出条件：

- 人工注入一个未分类样例时门禁非零，删除后恢复为零。
- 当前命中全部有明确分类和后续阶段，不能用一个总 allowlist 吞掉目录。
- 所有引用文件真实存在，Q-TABLE-04 使用一线城市 500 元的正确口径。
- 基线命令、测试数量、数据库水位写入执行记录。
