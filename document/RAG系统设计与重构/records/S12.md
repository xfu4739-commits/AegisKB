### Table provider 稳定边界结论

结论：长期保留当前 table provider，但只保留一个深接口，不保留 compatibility facade。

- 普通 chunk retrieval 无法等价提供受控 operation/filter/selected-column plan、冻结 table schema、Java query execution 和可回源 row/cell identity 的组合契约。
- `TableRetrievalChannel` 不解释 route、KB/document/task scope 或 query，只投影单一 `RetrievalExecutionRequest` 并执行 controlled table intent；运行结果必须重新对账同一 request 的 document-task pair。
- 长期边界是 `controlled plan + frozen schema + row/cell evidence identity`。如果未来普通 retrieval owner 能在单一 request 下原生承担这三个职责，应直接收拢 provider 并删除本 channel；不得增加双 request、pass-through service 或多层 adapter。
