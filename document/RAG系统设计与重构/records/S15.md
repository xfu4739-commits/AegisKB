## 实现结果

- 新增不可变 `AnswerShapePlan` 和受控枚举 `COMPARE/LIST/STEPS/NEGATIVE_BOUNDARY/CATEGORY_TABLE_ROW_COVERAGE`。
- `QueryUnderstandingService` 是唯一 JSON 校验 producer：仅接收 `answerShape` 数组；未知、非文本、空文本或低置信度计划整体 fail closed 为 empty。
- `RagPromptAssemblyService` 是唯一业务 consumer：五类只生成答案组织要求；category/table-row coverage 只有在真实 rendered Source 具有 `tableId`、`DOCUMENT_TABLE` 或 `TABLE_CELL_OR_ROW` typed identity 时才生效。
- `CATEGORY_TABLE_ROW_COVERAGE` 只要求问题相关分类及其值，不要求枚举整表；没有 table Source 时 fail closed 不投影该要求。
- `NEGATIVE_BOUNDARY` 不再进入 RetrievalPlan、ExecutionRequest 或 final evidence applicability；target/excluded entity 的既有通用明确匹配仍由 RetrievalPlan 解释。
- 删除运行代码中的 `expectedEvidenceRoles`、`answerExpectation`、`NORMAL_QA`、`EXPLICIT_EVIDENCE_REQUIRED`、`explicitEvidenceRequired` 和 retrieval `negativeBoundary` 字段/consumer。
- `RagPromptAssemblyResult/RagChatExecutor` 的 `answerShapeRequirements` 只记录实际应用的 Prompt 投影，不形成第二决策权威。
- Answer Shape 不解析、补写、替换或重排 `[n]`；`ExplicitCitationBindingService` 未修改生产算法。

## 上游不变与 citation 守恒

- `RetrievalPlanAssemblerTest` 对同一输入启用全部五类 Answer Shape，断言 `RetrievalPlan` 和 `RetrievalExecutionRequest` 递归完全相等。
- `RagPromptAssemblyServiceTest` 对同一受控 candidate/final Source 断言 candidate IDs、final Source identities、reference manifest、rendered Source/Context identities 和 canonical `referenceId -> identity` 映射完全相等；唯一变化是 Answer Shape Prompt 分区。
- `ExplicitCitationBindingServiceTest` 使用同一 eligibility 构造两个合法答案：答案 A `[2][1]` 得到 `identity-2, identity-1`，答案 B `[1]` 只得到 `identity-1`。每个答案内部 explicit/binding source snapshot 同序守恒，且明确不要求跨答案 identities 相等。
- Context、未渲染 Source、未知/越界 token 的既有 fail-closed 测试继续通过。
