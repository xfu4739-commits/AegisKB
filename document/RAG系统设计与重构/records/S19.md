### BLOCKING_FAIL：kb_search 全局 ToolCallback 循环依赖（S19 自身缺陷，owner=P4）

- 现象：`java -jar` 启动失败，Spring `UnsatisfiedDependencyException` 循环依赖：`ChatModel → toolCallingManager → toolCallbackResolver → kbSearchToolCallback(ToolCallback) → KbRetrievalTool → RagRetrievalEngine → ObservedChatModelService → ChatModel`。
- 根因（CODE_CONFIRMED）：P4 在 `ChatAgentConfiguration` 把 `kb_search` 注册为全局 `@Bean ToolCallback kbSearchToolCallback`。Spring AI `toolCallbackResolver` 自动收集所有 `ToolCallback` bean，使该 bean 经 `KbRetrievalTool` 传递依赖回到 `ChatModel`，与 `ChatModel` 自身形成循环。`tavily_search` 无此问题（`TavilySearchTool` 不依赖 `ChatModel`）。
- 为何单测未捕获：chat 模块 29 用例均为 Mockito 单测，不加载 Spring 上下文，无法暴露 bean 装配循环。
- 修复（最小、符合权威边界）：删除全局 `@Bean kbSearchToolCallback`；改为在 `sagChatReactAgent` 内联构造 `FunctionToolCallback`（局部变量），仅该 SAG agent 持有。`ReactAgent` bean 不被 `toolCallbackResolver` 收集，循环消除。`kb_search` 仍只属于 SAG agent，语义不变；`businessChatReactAgent`、`tavilySearchToolCallback` 不变。未使用 `allow-circular-references` 兜底。
- 实际修改：`aegis-kb-business/aegis-kb-business-chat/src/main/java/org/aegiskb/ai/chatagent/config/ChatAgentConfiguration.java`（删全局 @Bean；`sagChatReactAgent` 注入 `KbRetrievalTool` 并内联构造 `kb_search`）。

### 构建环境勘误（非源码缺陷，不改生产代码）

- 现象：修复循环依赖后增量 `mvn package` 仍启动失败，报 `java.lang.Error: Unresolved compilation problem: The code of method $deserializeLambda$(SerializedLambda) is exceeding the 65535 bytes limit`，定位 `DocumentRagArtifactServiceImpl`（与 SAG 无关）。

- 处置：`mvn -pl ... -am clean package` 强制 javac 全量重编译（572 源文件），无 `code too large`，jar 内为正确 javac class。仅构建卫生操作，未改任何源码（`DocumentRagArtifactServiceImpl.java` 未触碰）。
