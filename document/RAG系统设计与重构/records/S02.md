## 实现结果

### Python 工具边界

- similarity 只在每个 answer segment 内收窄候选，不再产生补引结论。
- 方向推理固定使用“evidence 为 premise、answer segment 为 hypothesis”的 NLI 输入顺序。
- response 只返回 `assessments`，每项包含稳定 `evidenceId`、segment/rank、`similarityScore`、`relation`、`confidence`、`reason` 和 source 定位信息。
- 受控关系只有 `SUPPORTS / CONTRADICTS / UNRELATED`；模型没有显式 NLI label、输出非法或不可用时返回工具失败，不回退到 similarity。
- 删除旧 `citations` 和 `score` 兼容字段，没有长期双协议。

### Java 决策边界

- 校验 response、assessment 数量、必填字段、受控枚举、有限概率、segment/rank 范围；非法响应统一 `FAILED_CLOSED_INVALID_RESPONSE`。
- rag-tools 异常统一 `FAILED_CLOSED_TOOL_ERROR`；回答后处理继续，但不产生 document repair citation。
- `SupportDecision` 是 relation、source boundary、`0.90` 置信阈值和去重的单一决策结果；引用 mutation 与 O9 投影消费同一结果。
- 只有边界内、置信度不低于 `0.90` 的 `SUPPORTS` 可进入最终 repair citation。
- `CONTRADICTS`、`UNRELATED`、低置信支持、越界 ID 和重复支持分别记录明确 disposition。
- `EvidenceApplicabilityResult.NOT_APPLICABLE` 是 citation repair 消费的唯一不适用状态 token。
- 方向判定 premise 优先使用 mapper 保留的原始 `quoteText`；仅在原始 quote 为空时回退到 generation-visible `snippet`，避免检索 wrapper 中的 query echo 被当成来源事实。

### O9 增量

- `CITATION_REPAIR` 记录 direction status/count、每个 sentence-candidate 的 relation/confidence/reason/final disposition、accepted support、removed candidates 和 final citations。
- 候选与逐 pair assessment 同时记录 `directionPremiseText` 和 `directionPremiseSource`；来源受控为 `ORIGINAL_SOURCE_QUOTE / GENERATION_VISIBLE_SNIPPET`。
- fail-closed 时 stage 标记失败并保存诊断；即使没有 trace recorder，也会输出 warning，而不是静默丢失原因。
