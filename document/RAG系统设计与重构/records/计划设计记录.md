# 计划设计记录

## 2026-07-10 / PLAN-BOOTSTRAP / 从问题基线形成单体计划

- 输入证据：当前源码、现有测试、数据库反例、旧 exchange、文档解析产物和运行日志。
- 初始问题：Prompt/citation 越界、Source/Context 混用、RetrievalPlan 多解释点、fusion/rerank/final selection 多权威、Markdown 结构压平、GraphRAG 样例语义、O9 不守恒。
- 设计方法：逐项追踪 producer、transition、consumer，区分 `CODE_CONFIRMED`、`DATA_CONFIRMED` 与 `HYPOTHESIS`；先提取跨问题不变量，再建立实施依赖。
- 初始结果：形成一个包含问题地图、总体原则、实施顺序、测试门禁和真实验收边界的单体改造计划。
- 关键决定：Java 保持业务主链路，Python 保持算法工具箱；不因为语言不同重写成熟算法边界，也不允许 Python 接管业务 scope、final evidence 或业务库状态。

## 2026-07-10 / DOC-CONSOLIDATION / 收口施工入口

- 发现问题：能力差距、单问题诊断、总览和接力计划同时存在时，AI 新会话可能选择不同入口，形成多个状态权威。
- 候选方案：继续维护多份摘要；给旧文档加重定向；吸收有效事实并只保留一个活动计划。
- 最终决策：有效事实进入唯一责任文档，删除已经被吸收的并行施工入口；聊天历史和旧搜索结果不得恢复为权威。
- 文档职责：Agent 指令负责长期规则，活动计划负责状态和依赖，验收方案负责问题与口径，启动手册只负责环境。
- 验证：检查已删除文件名无活动引用、Markdown fence 配对、状态表唯一性和链接完整性。

## 2026-07-10 / DOC-HUMAN-BOUNDARY / 明确真实产品操作权限

- 发现问题：AI 可以运行测试和只读查询，但真实上传、重建、初始化和聊天会改变业务数据，若自动执行会让 cohort、水位和责任边界失真。
- 最终协议：自动工作完成后进入 `HUMAN_ACTION_REQUIRED`；AI 先冻结版本和水位，用户按清单操作，AI 再只读验收。
- 适用操作：创建/选择知识库、上传文档、触发 parse/index/GraphRAG/RAPTOR、执行初始化 SQL、产生真实 exchange。
- 禁止行为：AI 未获单独授权时通过浏览器、HTTP、脚本或数据库写入代替用户；不得写数据制造通过。

## 2026-07-11 / DOC-SPLIT / 单体计划拆分为 S00～S18

- 拆分原因：单体计划同时包含状态、证据、实施步骤、历史记录和下一会话提示，长度过大且难以控制 AI 每次只做一个边界。
- 拆分原则：按业务权威、producer/consumer 依赖、迁移顺序、可验证边界和人工操作边界分阶段。
- 形成结构：`改造计划与进度.md` 维护唯一状态；`当前阶段与下一步.md` 维护最新接力；`stages/` 保存任务合同；`records/` 保存执行证据；`验证规则.md` 保存共享反馈矩阵。
- 阶段依赖：先证据资格与引用，再 RetrievalPlan 与 Provider；再 ranking/final policy；再 Markdown 和 GraphRAG；最后 Answer Shape、O9、全量重建和终验。
- 会话协议：一个会话只执行一个阶段；阶段完成后停止；新会话按最小上下文恢复。

## 2026-07-11 / STATE-MACHINE / 增加重开和暂停语义

- 普通状态：`NOT_STARTED / IN_PROGRESS / HUMAN_ACTION_REQUIRED / BLOCKED / DONE`。
- 新问题：后续真实验收可能推翻已经 `DONE` 的前置结论，不能篡改历史或把当前阶段直接当作 owner。
- 设计结果：增加 `REOPENED`、`activeReopen`、`successorBaseline` 和唯一 `suspendedReopen`；重开 owner 接管 currentStage，后继状态冻结。
- 原子恢复：owner 退出证据完成后，必须在同一次 改造计划与进度 修改中恢复 owner=`DONE`、currentStage=previousCurrentStage 并清空 descriptor。
- 门禁目标：让上下文压缩、新会话和多次重开仍能从磁盘状态确定唯一执行前沿。

## 2026-07-21 / PLAN-COMPLETE / 完成审计

- S00～S18 全部 `DONE`，`activeReopen=null`，`suspendedReopen=null`。
- 48-case 最终分类：`PASS=29 / BLOCKING_FAIL=0 / OBSERVATION_ONLY=19`。
- 计划价值：阶段文件保留原设计，records 保留真实偏差和重开；状态机保证 AI 在多个会话和真实人工操作之间能够恢复。
