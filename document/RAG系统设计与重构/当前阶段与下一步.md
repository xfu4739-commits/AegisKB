### 用户操作清单（真实验收，必须由用户执行）

1. 选定或准备一个真实验收知识库（存在 KB scope），确保目标文档已成功上传、解析并索引（真实上传/重建由用户执行）。
2. 启动后端 `aegis-kb-business-chat` 服务。
3. 在该 KB 聊天中提出一个**自然需要多跳迭代检索或内外证据对照**的问题，使 QueryUnderstanding 在高置信度（>= 0.72）下产出 `MULTI_HOP_RESEARCH`，经 `DocumentQuestionRouter` 翻译为 `ExecutionMode.SAG`。禁止用业务词/词表/文档名诱导路由。
4. 触发一次真实 exchange，确认其走 SAG 分支（trace 出现 `SAG_SEARCH` 与 `SAG_FINALIZE` 阶段码）。

### AI 只读核对项（用户完成 exchange 后）

- `kb_search` 每次调用 scope 与冻结 `RetrievalPlan` 完全一致，无越界/未知 identity（fail closed 未触发）。
- final selection 只在阶段2对合并窗口执行一次；per-call 候选无 `FINAL_EVIDENCE_POLICY` decision。
- 循环内模型中间文本未进入 answer 流；最终答案只来自阶段2 `rag_answer`。
- web（tavily_search）证据渲染为 `PROMPT_RENDERED_CONTEXT`，不出现在 `explicitCitationEligibleIdentities`、final policy 或 archive source snapshot。
- 答案合法 ASCII `[n]` token 与同轮 rendered/reused Source identities 同序守恒；无合法 token 时 binding/FINALIZE/archive 数组为空。
- O9 统计与最终归档守恒合法。
- 模型理解/reranker/答案生成质量波动，在 scope、Plan/request、证据资格、citation、O9 均合法时只记 `OBSERVATION_ONLY`；只有本项目 producer/transition/consumer 违反明确 authority/invariant 才记 `BLOCKING_FAIL`。

## 必须保留的边界

- Java 是 RAG 业务主链路，Python 是算法工具箱。
- 一个业务决策只有一个权威；`RetrievalPlan` 只解释一次 scope/channel/预算/排序特征，SAG 循环只新增"调用时机与查询文本"自由度。
- final selection 每次 exchange 只执行一次（阶段2对合并窗口）。
- 最终答案只能由阶段2 manifest 渲染 + 生成产出；循环内模型文本不作为 answer。
- Source Evidence 与 Context Only 硬分池；web 结果仅 Context Only，无 `[n]` 资格。
- 最终 citation 只由答案合法 ASCII `[n]` 绑定同轮 rendered/reused Source。
- 真实上传、重建、初始化和聊天默认由用户执行。
- 模式决策不新增业务词、词表、文档名或 contains 规则。
